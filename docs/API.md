# API

Все эндпоинты — на одном FastAPI-сервисе (`winescanner/app.py`). После
запуска живая документация доступна по `/docs` (Swagger UI).

## Публичные, без авторизации

| Путь | Метод | Что делает |
|---|---|---|
| `/` | GET | Страница поиска (`static/index.html`) |
| `/health` | GET | `{"ok", "model_loaded", "catalog_size", "eval_mode"}` — статус сервиса |
| `/catalog` | GET | Весь каталог одним JSON |
| `/photos/{filename}` | GET | Оригинальное эталонное фото каталога |
| `/photos_thumb/{filename}` | GET | Миниатюра эталонного фото (длинная сторона 500px) |
| `/query_log/{request_id}.jpg` | GET | Сохранённое фото конкретного запроса |
| `/v1/stats` | GET | Агрегаты качества по ручной разметке |
| `/v1/metrics_doc` | GET | Текст `docs/METRICS.md` для окна-объяснения на странице |

## Основное распознавание

### `POST /v1/predict`

Заголовок `X-API-Key` обязателен. Тело — `multipart/form-data`, поле
`image` (`.jpg`/`.webp`).

Ответ (JSON):

```json
{
  "slug": "vinodelnya-...",
  "confidence": 0.83,
  "found": true,
  "card": { "...": "полная карточка вина из wines.csv" },
  "top5": [
    {"slug": "...", "similarity": 0.83, "rerank_score": 0.98, "...": "..."}
  ],
  "low_res_warning": false,
  "low_res_message": null,
  "vlm_extracted": { "...": "структурированный текст, прочитанный VLM" },
  "vlm_json_ok": true,
  "timing_ms": {"embed": 3100, "vlm": 7300, "total": 10500}
}
```

Значения полей (`similarity`, `rerank_score`, `confidence`,
`low_res_warning`) — [`METRICS.md`](METRICS.md).

### `POST /v1/mark`

Разметка человеком: какой из топ-5 верный (или что ни один не подошёл) —
для подсчёта точности. Тело: `{"request_id": "...", "marked_slug":
"slug", "not_in_catalog": false}` (`marked_slug: null` — «ни один не
подошёл»; `not_in_catalog: true` — вина нет в каталоге, исключается из
знаменателя точности). `request_id` берётся из ответа `/v1/predict`.

## Пакетная обработка

| Путь | Метод | Что делает |
|---|---|---|
| `/v1/batch/upload` | POST | Заливает один файл в стейджинг пачки (`batch_id` + `image`) |
| `/v1/batch/run` | POST | Запускает обработку пачки в фоне, отвечает сразу |
| `/v1/batch/status/{batch_id}` | GET | Прогресс и готовые результаты пачки |

Работает поверх того же ядра, что и `/v1/predict`; результаты попадают в
тот же журнал и статистику.

## Контрактный эндпоинт (внешняя автоматическая проверка)

Пара эндпоинтов без авторизации, регистрируются флагом
`WINESCANNER_ENABLE_CONTRACT_ENDPOINT` (см. [`DEPLOYMENT.md`](DEPLOYMENT.md)).
При `false` оба отдают `404`.

### `POST /v1/eval/predict`

`multipart/form-data`, поле `image`. Ответ: `{"slug": "wine-slug"}`
(также поддерживается массив `[{"slug": "..."}]`). Ответ урезан до
одного `slug`.

Контракт вызывающей стороны: один запрос в момент времени, без
параллелизма и повторов; жёсткий лимит 10 секунд на запрос (не успел —
засчитывается как отсутствие ответа).

### `POST /v1/topk`

`multipart/form-data`, поле `image`. Ответ — укороченный список
`[{"slug": "...", "confidence": "..."}, ×5]`.

При включённом контрактном эндпоинте одиночное распознавание
(`/v1/predict`) продолжает работать — доступ к модели сериализуется, один
запрос сайта и контрактный запрос укладываются в лимит 10 с.
Блокируется (`503`) только пакетная обработка (`/v1/batch/run`): пачка
держит модель до минуты и может сорвать лимит.
