# Технологический стек

## Модели

| Модель | Назначение | Как подключена |
|---|---|---|
| `Qwen/Qwen3-VL-Embedding-2B` | Визуальный эмбеддинг фото для поиска по каталогу | В процессе `winescanner`, через `sentence-transformers` (PyTorch, CUDA) |
| `Qwen/Qwen3-VL-4B-Instruct` | Чтение текста этикетки → структурированный JSON | Отдельный процесс — сервер vLLM, OpenAI-совместимый HTTP API |

Обе модели — предобученные, без дообучения под каталог; веса скачиваются с Hugging Face при первом запуске.

## Инфраструктура

- **GPU**: NVIDIA, CUDA 12.1 — эмбеддинг и VLM работают на одной видеокарте последовательно (`_inference_lock`), обоснование — [`ARCHITECTURE.md`](../ARCHITECTURE.md).
- **Docker**: два образа в `docker-compose.yml` — `winescanner` (собственный `Dockerfile`, база `ubuntu:24.04`) и официальный `vllm/vllm-openai`; раздельно, так как их версии PyTorch несовместимы в одном окружении.
- **vLLM-флаг `--enforce-eager`**: отключает JIT-компиляцию (`torch.compile`) движка — предсказуемый холодный старт вместо разового долгого прогрева кэша компиляции.
- **Reverse proxy / HTTPS**: Caddy — автоматический TLS (Let's Encrypt), конфигурация — [`docs/DEPLOYMENT.md`](DEPLOYMENT.md).
- **Process manager**: systemd-юниты для ручного (не-Docker) запуска — там же.

## Препроцессинг фото

- **Пиксельный бюджет**: нормализация размера кадра перед подачей в любую модель (`MIN_PIXELS=50_000`, `MAX_PIXELS=2_000_000`) — одинаково для эталонов каталога и запроса, иначе эмбеддинги несравнимы.
- **BOTTLE_CROP** (экспериментальный, выключен по умолчанию): выбор объекта на фото через YOLO11 (`ultralytics`) — не входит в основной пайплайн.

## Фронтенд

Один статический HTML-файл (`winescanner/static/index.html`) — без сборки, без фреймворка, без отдельного шага компиляции.

## Данные

- Каталог: `wines.csv` (метаданные) + эталонные фото + предвычисленные эмбеддинги, формат и структура — [`data/README.md`](../data/README.md).
- Алиасы производителей/сортов винограда и частотный словарь каталога (для реранкинга) — JSON/pickle-файлы в `winescanner/`.

## Чего в стеке нет

- Внешние платные облачные API в рабочем пайплайне — все вычисления локальные.
- Отдельная векторная база данных — каталог сравнивается в памяти (NumPy).
- Отдельный OCR-движок — текст читает та же VLM, что видит фото.
- JS-фреймворк на фронтенде.
